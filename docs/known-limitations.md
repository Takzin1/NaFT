# Known limitations — MRV Core

- **Reference methodology only**: AG-005 `3.1-reference` originates from a public-comment attachment previously recorded on 2026-09-10. Current adoption and applicable coefficients remain unconfirmed. CONFIG REQUIRED persists through human attestation; certified reduction result is null.
- **One static Rule Pack**: exact version/hash pinning and prototype release approval exist. Multi-version migration, rule-diff impact analysis, effective-date selection, external update discovery and arbitrary Pack loading are not implemented.
- **Evidence adapters**: file bytes plus operator metadata only. No OCR, semantic normalization, document-content conflict inference, authenticity proof, malware scan or original-file storage. Upload limit 5 MiB. Different hashes in one category/year are potential conflicts, not proof that contents contradict each other.
- **Identity**: normalized caller-provided field IDs only; no cadastral/GIS reconciliation, geometry overlap, aliases across datasets or cross-registry duplicate search.
- **Human boundaries**: minimum-length reasons do not assess quality. Hard failures cannot be overridden. Reference-pack approval and final package attestation do not resolve official configuration or replace formal external verification.
- **Corrections**: no general activity editor, manifest withdrawal/replacement, attestation amendment/revocation or cross-version reprocessing workflow. Pre-attestation test scenarios may use new activities or current supported evidence operations; altered data invalidates prior evaluations.
- **Client trust**: demo identities and scope checks run in the browser. Reviewer has all demo Program visibility; this is not a production multi-tenant permission model. Whole-dataset replacement plus rehashing remains possible. Hash chains are not independent signatures or external audit witnessing.
- **Persistence**: memory-only outside Artifact storage. Single JSON document, no concurrent-writer transaction isolation. A failed persistence call is surfaced but already-applied in-memory mutations are not rolled back. Legacy schemas are not migrated.
- **Reproducibility scope**: same saved evaluation/decisions/attestation produces identical canonical export. Independent sessions create different IDs and timestamps. Audit validation is full-history linear; event-binding lookups and selected-field checks can add further cost. Full snapshots remain in memory and exports can be large.
- **UI**: Node tests use a DOM stub. Cloud Browser rejected the local file URL under its URL policy. Browser layout, real file-input replacement, download behavior, keyboard accessibility and mobile interaction are not established by those assertions. Evidence paging retains input nodes; route/actor/activity changes can discard unfinished text.
- **Validation**: no field PoC, third-party verifier acceptance, measured administrative cost savings or production-scale concurrency result is claimed.
