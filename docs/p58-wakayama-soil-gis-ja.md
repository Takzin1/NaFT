# NaFT P58｜和歌山県農耕地土壌GIS：来歴・行政属性監査・安全な再利用

## 対象と原本保全

ユーザー提供の `和歌山県.zip` を2026-11-10に監査した。元ZIP 5,134,115 bytes、SHA-256 `c663a62ae93deb5672cc7645ec9ec98d18b1bb80171171ce1c74f8b591090453`。中には `k30和歌山県` のDBF・PRJ・SBN・SBX・SHP・SHP.XML・SHX計7ファイルがある（計8,261,834 bytes）。各ファイルのSHA-256・容量は研究台帳を参照。

SHP・SHX・DBFは**いずれも822ポリゴン**で一致。元データはESRI POLYGON (shapeType 5)、GCS_JGD_2000。境界は `[135.06211223455733,33.440356351953994,135.99644666955822,34.3795490128588]`。ZIP内部パスはCP932復号、元ファイルのバイトハッシュまで記録済み。XML原本作成日2017-01-17で、2026年の現地観測を意味しない。

出典の候補は農研機構「日本土壌インベントリー」 https://soil-inventory.rad.naro.go.jp/download5.html だが、公式ZIPとのバイト単位SHA照合、発行者による個別認証、ライセンス・再配布許諾は未確認。したがって**生ZIP・SHP・DBF・地物座標をGitHubに公開しない**。公開するのは検証手順・ハッシュ・派生集計のみ。

## 再現性とテスト

- `research/p58-wakayama-soil-shapefile-source-v1.json`：元ZIP/7ファイルのハッシュ、JCODE×名称64組、GUN×名称44組、要照合警告、科学的な制約。
- `scripts/p58-wakayama-soil-audit.py`：標準ライブラリだけで動作。公開CIでは `audit`、元ZIPがある環境では `verify` を実行。`verify` はZIP・全7構成ファイルのSHA-256、SHP全822レコードとSHXのオフセット対応、DBF全822行のCP932属性を独立検査。
- `src/gx-wakayama-soil.js`：GX Data AtlasのprefCode `30`で地目別カード・原本JCODE/GUNテーブルと要照合警告を表示。未正規化であることを明示。
- `tests/p58-wakayama-soil-gis.test.mjs`：元ZIPのハッシュ定数、派生件数、異常値、改変検知、既存29都道府県の回帰接続を検査。

公開CI：

```bash
python3 scripts/p58-wakayama-soil-audit.py audit
node tests/p58-wakayama-soil-gis.test.mjs
```

提供原本を保有する**ローカル環境のみ**でバイト・全レコード再検証：

```bash
python3 scripts/p58-wakayama-soil-audit.py verify '/private/和歌山県.zip'
```

公開CIの `audit` が成功しても**原本ZIPの全バイト検証がCI上で走ったことにはならない**。元ZIPを投入したローカル側では `verify` を実施し、全822レコード一致を確認済み。

## 科学的・制度的な利用制約

ポリゴン件数は面積ha、圃場筆数、土壌炭素量、GHG観測値、CO₂e削減量、認証済みJ-クレジット発行量のいずれでもない。現行行政コード・2024年水稲統計・JAXA土地被覆と機械的にJOINして自治体別確定統計を作らない。行政区境界の年代差・幾何照合・コード照合を経て、人による確認を行ってから別レイヤーで使用する。
