# NaFT｜技育展向け日本語版

**入口**：リポジトリ内の [gikuten.html](../gikuten.html) を開きます。GitHub Pagesで公開する場合は /NaFT/gikuten.html#/reviewer-demo の形式になります。ただし、このブランチはPagesの公開ブランチではないため、PR作成時点でPages URLを公開済みと判断しないでください。

## 日本語版の範囲

- 審査員向けデモ、変更影響解析結果、代表案件と人間判断の説明、6つの研究用操作画面の表示テキストを日本語化
- 版管理・証憑・判定・権限・監査・監視用JSONのデータキーや列挙値は元の実装をそのまま利用
- 同じ合成入力、同じ解析関数、同じパッケージ生成ロジックを共用。翻訳層が数値を差し替えることはない
- 元の naft-app.html は変更しない。IEEE/研究向け画面を維持
- ソースコードの識別子、機械可読JSON、ハッシュ、正式な状態コードは必要に応じ英語表記を維持。操作と説明は日本語で完結可能

## 審査用60秒デモ

1. 日本語版の「100件の変更影響解析を実行」を押す。
2. 合成方法論 NAFT-SYNTHETIC v1 → v2 の更新で、対象100件、要再検証30件、影響なし70件、自動再評価15件、追加証憑が必要15件を表示。**すべて実際の解析結果から計算**。
3. 代表3件を展開し、何が変更され、なぜ要再検証か／影響がないかを追跡する。
4. 「人間判断の失効を見る」を押し、入力または方法論ルールが変わると以前の判断が使えなくなることを示す。
5. 下部の「通常の6ステップ研究UIへ」から、方法論登録、証憑取込、決定論的評価、例外判断、最終確認、JSON出力まで見る。

## 絶対に誤解させないこと

100/30/70/15/15は **standard 70件、intensive 15件、intensive_complete 15件の合成データ構成**に由来します。実際のMRV業務の効率改善率、費用削減率、時間短縮率、精度、行政・検証機関の受入れを証明しません。

AG-005の参照版は正式制度への対応を保証しません。制度要件・係数が未確定の場合は確認が必要な状態で止め、正式な認証結果を生成しません。

## ローカル実行

ビルド・CDN不要。プロジェクトルートで簡易サーバーを起動してください。

    python3 -m http.server 8000

次にブラウザで localhost:8000/gikuten.html を開きます。テストは bash tests/run.sh を実行します。

日本語版の翻訳は src/gikuten-ja.js、外観は src/gikuten.css で管理します。翻訳は描画後の可視文字に限定し、操作に使う select option の値は元の状態コードを保持します。技術資料・英語UIの変更を日本語訳に巻き込まない設計です。
