# Human-on-the-exception + Human-at-the-attestation

The machine prepares reproducible evidence packages. Human judgement is required only where rules do not settle the question and at the final attestation boundary.

| Operation | Machine | Human boundary |
|---|---|---|
| Completeness / hash / version / dates / duplicate checks | Deterministic execution | Correct failed inputs; no routine approval per check |
| Calculation / provenance / package draft | Deterministic construction | Configuration limitations remain disclosed |
| Conflicting evidence | Detect multiple content hashes for the same category/year | Reviewer accepts the relationship with a reason or rejects it |
| Unsupported method/land condition, missing/tampered evidence, invalid dates | Blocking exception | Reviewer may reject; acceptance cannot override the failure |
| Methodology Pack release | Verify exact Pack hash | Maintainer approves reference use once per Pack |
| Final package attestation | Recheck current inputs, evaluation, decisions, Pack approval and audit | Reviewer provides a statement and explicit acknowledgement once per package |
| Formal external verification | Not implemented | Remains outside this application |

A normal complete case has no separate readiness approval, candidate-record approval or per-category approval. The evaluation button requests computation, not approval. Package draft generation is a pure projection, not a human gate.

All available packs currently have unresolved official configuration. This is a disclosed global limitation, acknowledged at final attestation; acknowledgement never fills unknown coefficients or changes reduction.result from null. Sustainability is an operator declaration, included in the final human review scope, not proof of compliance.

Judgement decisions are bound to an evaluation ID, input fingerprint, reviewer, timestamp and reason. Re-evaluation invalidates their applicability. Rejection blocks final attestation. Minimum 20-character reasons enforce presence only, not substantive quality. There is no AI model or automatic certifier.

Actions verify active demo role and Program scope. After attestation the supported API locks attachments and replacement evaluations. Correction/amendment/revocation of attested packages is not implemented.
