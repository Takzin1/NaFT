# Web3トークン取引の法務論点整理（2026-11-25時点）

NaFTを「Web3トークンを取引できる」ようにする場合に、事前に確認すべき論点の整理です。**法的助言ではありません。** 実装に進む前に、弁護士等の専門家による個別の確認が必要です。各項目の確認の深さは「確認状況」の列に記載しています。

関連：[Web3 来歴アンカー 設計書](web3-provenance-anchoring-design-ja.md) ／ [MRV表示とデータの境界](legal-risk-map.md) ／ [既知の制約](known-limitations.md)

## 0. 結論（現時点）

- NaFTは**取引可能トークンを実装しません**。`LICENSE` と `AGENTS.md` の境界は変更していません。
- 最大の障害は法令以前にあります。**NaFTにはトークンが表すべき「認証済みクレジット」が存在しません**（`result: null`）。未認証の値にトークンを結び付けて流通させると、削減量の誤認や二重計上の経路になります。
- 実装したのは、価値も数量も持たない来歴アンカーだけです（[設計書](web3-provenance-anchoring-design-ja.md)）。

## 1. 前提の区別

| 区別 | 内容 | NaFTの立場 |
| --- | --- | --- |
| GHGインベントリ算定 | 企業が自社の排出・吸収を報告する。GHG Protocol LSR Standard v1.1 など | 実装しない。二次資料によれば、購入したクレジットはインベントリと分けて報告し、相殺しない扱い（原文未確認） |
| カーボンクレジット | 制度（J-クレジット等）が方法論に基づき認証・発行し、登録簿で移転・無効化する | NaFTは発行も認証もしない。事前チェックのみ |
| トークン | ブロックチェーン上の記録。法的性質は**背後の権利と取引態様**で決まる | 来歴アンカーのみ。権利を表さない |

## 4. 表示・消費者保護の論点

- 未認証の数値を「削減量」「クレジット」と表示すると、景品表示法上の不当表示や、いわゆるグリーンウォッシュの問題になり得ます。一般的な論点で、個別には未確認です。
- 既存の [MRV表示とデータの境界](legal-risk-map.md) は、内部PASS・Pack承認・人間の最終確認を、正式な認証や削減の証明と表現することを禁じています。

## 5. 取引機能を検討する前に必要な条件（ゲート）

取引可能トークンを再検討する場合は、少なくとも次がそろってからにしてください。

1. **裏付け**：トークンが表すのは、制度が発行した認証済みクレジットであり、NaFTの評価結果ではないこと。登録簿上の識別番号と1対1で対応すること。
2. **二重計上の防止**：登録簿での無効化・移転とトークンの発行・償却を同期する手順。片方だけが動いた場合の復旧手順。
3. **法務意見**：発行主体、権利内容、取引態様を特定したうえでの、金融商品取引法（改正後の暗号資産取引業を含む）・資金決済法・犯罪収益移転防止法・景品表示法・税務・会計についての書面の見解。
4. **制度側の確認**：J-クレジット制度事務局等の規程が、トークン化や外部台帳での表示を認めているか。
5. **リポジトリの境界変更**：上記を踏まえた `LICENSE`・`AGENTS.md`・`legal-risk-map.md` の改訂。改訂はプロジェクトの所有者が明示的に判断する。
6. **技術**：鍵管理、監査済みコントラクト、停止・回復手順、本番と研究の分離。
